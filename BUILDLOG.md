## Where the AI was wrong / things that went sideways (real events from the session)
1. **Probe 5 first failed** — my probe script checked for the permanently-failed job immediately, but retries use exponential backoff (`base ** attempt` seconds), so the job wasn't failed yet. The app was right; the probe was wrong. Fix: the probe now polls up to ~30 s, and the Docker default backoff base was lowered to 1.5 so the demo finishes in ~10 s.
2. **A Postgres pitfall avoided by design** — patterns like `WHERE (:widget_id IS NULL OR widget_id = :widget_id)` fail on PostgreSQL (untyped parameter). The repository layer builds the `WHERE` clause conditionally from constant fragments instead.
3. **Environment slip** — while restarting the test server, two `pkill -f` / PID-lookup commands matched their own shell and killed it. Not a project bug; the restart procedure was changed to run the server and the probes in the same command.
4. **Behaviour that is surprising but deliberate:** with the live worker running, *earlier* pending email jobs also fail while the "email down" fault is switched on (the worker is real and concurrent). That is why several `ALERT` lines can appear during probe 5.
